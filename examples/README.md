# 示例代码库

这里包含可复现的代码示例，展示梁文锋式思维如何发现和修复问题。

## 文件说明

| 文件 | 说明 |
|------|------|
| [buggy.py](buggy.py) | 有问题的版本，包含 4 个典型漏洞 |
| [fixed.py](fixed.py) | 修复后的版本，应用了五大原则 |
| [diff.md](diff.md) | 具体修改对比 |

## 快速运行

```bash
# 运行有问题的版本
python buggy.py

# 运行修复后的版本
python fixed.py
```

## 这个示例展示了什么

### 问题版本的 4 个典型问题

1. **模型重复加载**（稀疏化问题）
   - 每次 `FaceAuthSystem()` 都加载一次 ArcFace
   - 浪费 ~600MB GPU 显存

2. **硬编码假通过**（不变量问题）
   - 异常时 `return 0.80`，调用方阈值是 0.85
   - "验证安全"这个不变量被架空

3. **TODO 权限占位**（不变量问题）
   - `return True // TODO`
   - "权限检查"这个不变量从未被保证

4. **反馈闭环断裂**（自监督问题）
   - `collect_feedback()` 收集了但没人用
   - "自进化"这个宣称从未实现

### 修复版本应用的原则

| 问题 | 应用原则 | 修复方案 |
|------|---------|---------|
| 重复加载 | 原则 2（稀疏化） | 单例模式，只加载一次 |
| 假通过 | 原则 1（不变量） | 返回明确失败值 0.0 |
| 权限占位 | 原则 1（不变量） | 真正实现权限检查逻辑 |
| 闭环断裂 | 原则 4（自监督） | FeedbackLoop 类，收集后自动适配 |
